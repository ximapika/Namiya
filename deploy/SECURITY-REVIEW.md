# 安全修复与部署验证（2026-09-20）

## 已修复

- 默认关闭 ProxyFix，防止直接暴露的服务信任伪造转发头而绕过按 IP 限流。
  可信代理场景须显式配置，参考 [Flask 官方说明](https://flask.palletsprojects.com/en/stable/deploying/proxy_fix/)。
- 登录与主题重定向只接受根相对路径，拒绝外站、双斜线、反斜线及控制字符。
- 退出登录改为带 CSRF 的 POST；动态页面设为 `Cache-Control: no-store`。
- 移除内联脚本和事件处理器，避免历史用户名进入 JavaScript 字符串；CSP 禁止内联脚本。
- 初始化不再提升已有同名账号权限或覆盖密码，示例配置不再包含默认管理员密码。
- 默认禁用 Flask debug；修复直接启动及目录包启动的导入兼容性。
- 加密器按应用隔离；旧密文在迁移前认证，错误密钥会中止，不能作为明文再次加密。
  新密文带版本前缀，旧格式仍可读取。密钥语义参考 [Fernet 文档](https://cryptography.io/en/latest/fernet/)。
- 生产限流使用回环 Redis，多个 worker 共享计数；独立服务账号、严格目录权限及 systemd 限制。
- 生产依赖锁定并使用 pip-audit 检查已知漏洞。

## Git 历史

发现历史提交中存在 5 份数据库快照。用户已批准清理发布历史；使用隔离 mirror 和
`git filter-repo --path worryshop.db --invert-paths` 清理，验证当前代码树不变，
再以精确 `--force-with-lease` 发布。旧克隆需要重新克隆或对齐，不能重新推入旧历史。
原历史仍存在于服务器受限的部署前备份中，以满足原数据保留要求。

清理分支历史不代表能撤回他人已经下载的数据，亦不能保证 GitHub 的旧提交缓存立即消失。
必要时由仓库所有者联系 GitHub Support 清理缓存引用。
